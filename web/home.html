03 · Trace & Observability

Trace Hook 可观测设计

不是事后打日志，而是在 ChatStreamer 的事件回调里「埋点」——每一步推理自动生成 Span，零侵入 Agent 核心逻辑。

🔍 Trace 链路结构

每条用户消息生成一条 Trace，内部由多个 Span 按父子关系嵌套：

root — 处理用户消息（handle_chat）
├─ agent — 客服智能体 reply_stream
│ ├─ think — 模型思考过程
│ ├─ text — 回复文本生成
│ ├─ tool — 工具调用决策
│ │ └─ tool_exec — 工具执行 + 结果回填
│ └─ event — 推理轮结束

🪝 Hook 埋点机制

在 ChatStreamer 的事件翻译层自动开合 Span，无需修改 Agent 内部：

• ToolCallStartEvent → begin_span(kind="tool")
• ToolCallEndEvent → close_span() + begin_span(kind="tool_exec")
• ToolResultEndEvent → close_span(tool_exec)
• ThinkingBlockDeltaEvent → 自动合并连续 think span
• TextBlockDeltaEvent → 自动合并连续 text span
• ReplyEndEvent → 关闭所有未闭合 phase span

🌲 调用树

单条 trace 的 span 按 parent 关系组织成层级树，逐节点展示耗时、状态与参数/结果详情。点击节点可展开参数和返回预览。

🔥 火焰图

按 (kind, name) 路径聚合多条 trace 的耗时，条宽即耗时占比。一眼定位是哪类操作（模型推理 / 工具执行 / 思考）占大头。

⏱️ 瀑布时间线

Span 甘特条 + reply_end 等瞬时事件打点，直观看到 TTFT（首 token 时间）与各工具耗时在整轮中的位置分布。

数据纯内存存储（TraceStore 环形队列，默认保留最近 200 条），无需外部依赖，开箱即用。

04 · Highlights

项目亮点

不止是调一个接口，而是把 Agent 从「demo」做到「工程化」。

🧠

完整 ReAct 链路

基于 AgentScope 2.0 Building blocks，真实呈现「思考 → 工具 → 回复」编排，而非简单问答。

🔧

17 个业务工具

订单 / 物流 / 退款 / 购物车 / 商品 / 会员 / FAQ / 工单 / 转人工，覆盖电商全流程。

🛡️

不编造数据

查询类工具 is_read_only=True，写操作先说明并征得同意，真实可信。

⚡

SSE 流式体验

思考过程、工具调用、回复增量实时逐段推送，前端分卡片展示。

🔄

服务降级保障

主模型超时/异常自动降级到离线规则模型，业务零中断；支持配置超时阈值与降级策略。

👥

多会话隔离

每会话独立 Agent，上下文存 AgentState，含 LRU 淘汰与闲置回收。

🔥

可观测调试平台

调用树 / 火焰图 / 瀑布时间线，把每一步推理链路「打开」给学生看。

🧾

管理后台

运营 / 人工客服处理工单、维护 FAQ、查看订单与会话。

🎯

开箱即用

一条命令启动，附演示订单与快速问题，适合课堂现场演示。
